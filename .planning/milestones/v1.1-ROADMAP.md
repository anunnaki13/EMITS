# Roadmap: EMITS — PLTU Tenayan Fuel Management

## Overview

This roadmap takes a live-production fuel management system (FastAPI + MongoDB + React on a single VPS, with real plant data already in flight) and brings it to a fully documented, fully tested, debt-resolved state before any new feature work begins. Phases 1–4 are pure stabilization (audit, fix login, document existing surface, get tests green). Phase 5 resolves the SPEC-flagged collection naming debt safely against live data. Phase 6 unblocks operational items that were blocked at ingest time (LLM budget, parser sample). Phases 7–8 carry the PRD's P2/P3 backlog (server modularization, advanced filtering, polish) — they intentionally come AFTER stabilization because the project owner is in learn-the-system mode.

### Phase 2: Authentication Stabilization
**Goal**: Login/auth gets out of the user's way — login works, sessions persist, role enforcement is honest, and a regression test guards the fix.
**Depends on**: Phase 1
**Requirements**: AUTHFIX-01, AUTHFIX-02, AUTHFIX-03, AUTHFIX-04, AUTHFIX-05
**Success Criteria** (what must be TRUE):
  1. User can log in with valid credentials and the session survives a browser refresh (verified by `GET /api/auth/me` rehydrate).
  2. User sees correct HTTP error codes on auth failures: 400 / 401 / 403 / 404 / 500 per CONS-auth-header.
  3. Admin/operator/viewer role enforcement is observably correct on at least one endpoint per role tier (e.g., admin-only delete-all, admin+operator upload with viewer denied — proven by `test_upload_vessel_role_gate` in `pltu-tenayan-full-backup/backend/tests/test_auth_roles.py`; viewer-readable list endpoints). Note: no truly operator-exclusive endpoint exists in the current codebase (admin shadows operator on upload), so the original "operator-only upload" wording was inaccurate; amended in Phase 3 plan 03-02 per D-13.
  4. The reported login bug no longer reproduces with the original repro steps from AUDIT-04.
  5. Zero credentials are committed to git; test credentials are loaded from local `memory/test_credentials.md` only.
**Plans**: 4 plans
  - [x] 02-01-PLAN.md — Credential hygiene gate (AUTHFIX-05) → gitignore + scanner + pre-commit hook + CREDENTIAL_HYGIENE.md
  - [x] 02-02-PLAN.md — Auth contract reconciliation + session rehydrate test (AUTHFIX-01, AUTHFIX-02) → 422→400 handler + 5-test regression suite + AUTH_CONTRACT.md
  - [x] 02-03-PLAN.md — Role enforcement regression suite (AUTHFIX-03) → 11-test parametrize suite over admin/operator/viewer tiers
  - [x] 02-04-PLAN.md — Login bug disambiguation + operator playbook (AUTHFIX-04) → LOGIN_BUG_RESOLUTION.md (autonomous: false)
