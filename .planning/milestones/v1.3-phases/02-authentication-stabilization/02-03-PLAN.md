Endpoints to exercise:
- `GET /api/vessels` — Depends(get_current_user) — any authenticated user (200)
- `DELETE /api/vessels` (delete-all) — admin only (operator/viewer → 403)
- `POST /api/upload/vessel` — multipart, admin OR operator (viewer → 403)
- `GET /api/users` — admin only (operator/viewer → 403)

`require_role` implementation (server.py around line 569):
```python
def require_role(allowed_roles: List[str]):
    async def role_checker(user: dict = Depends(get_current_user)):
        if user.get("role") not in allowed_roles:
            raise HTTPException(status_code=403, detail="Akses ditolak")
        return user
    return role_checker
```

So role denial returns 403 with detail "Akses ditolak". Tests assert on status code primarily; detail string is asserted as a soft check (Indonesian or English variant — server.py uses "Akses ditolak", routers/auth.py uses "Insufficient permissions").

Important — POST /api/upload/vessel without a real Excel payload:
- Sending `requests.post(url, files={"file": ("empty.xlsx", b"")})` will pass the role gate (admin/operator) and then fail Excel parsing → 400 with `"Gagal memproses file"` (server.py line 1175). For viewer, it's 403 from the role gate BEFORE parsing. So:
  - admin upload empty xlsx → 400 (NOT 200, NOT 403) — proves admin passes role gate
  - operator upload empty xlsx → 400 — proves operator passes role gate
  - viewer upload empty xlsx → 403 — proves viewer is blocked by role gate

This pattern lets us test role enforcement without inserting real vessel data into production. Critical: do NOT send a valid Excel payload — that would mutate production.

For DELETE /api/vessels (admin delete-all): we DO NOT want to actually delete the 111 production vessels. Mitigation: TWO-PHASE test using a `pytest.skip` flag controlled by env var `RUN_DESTRUCTIVE_TESTS=1`. By default, the destructive admin-DELETE-vessels test is SKIPPED. The non-destructive proof we always run: send DELETE /api/vessels as operator and viewer and assert 403 (the role gate fires before any database operation, so this is safe regardless of DB state). The admin-success path is asserted via env-gated test that operators run only against a non-prod database.
