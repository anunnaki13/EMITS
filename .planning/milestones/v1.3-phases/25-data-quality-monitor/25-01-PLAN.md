## Tasks

### Task 1 - Data Quality Service

Create `backend/services/data_quality.py`.

Implementation requirements:

- Define explicit rule config for stale thresholds, numeric ranges, and COA delta thresholds.
- Compute issues for:
  - stale stock/usage/PO/arrival/COA data
  - missing dates
  - duplicate operational keys
  - negative/unrealistic numeric values
  - COA outlier deltas
- Return deterministic issue objects with:
  - `key`
  - `module`
  - `collection`
  - `severity`
  - `type`
  - `field`
  - `source_record_id`
  - `source_label`
  - `source_path`
  - `message`
  - `suggested_fix`
  - `metadata`
- Provide:
  - `build_data_quality_report(module="all", severity="all", limit=100)`
  - `build_data_quality_export_rows(module="all", severity="all")`
  - `build_data_quality_caveat(module="all")`
  - `summarize_import_quality(dataset, records, issues)`
  - `summarize_coa_preview_quality(preview)`

Acceptance:

- Service functions can run directly against isolated test DB.
- No live secrets or live LLM required.
- Rule messages are Indonesian.

### Task 2 - Data Quality API And Export

Create `backend/routers/data_quality.py` and include it in `backend/server.py`.

Endpoints:

- `GET /api/data-quality/summary`
- `GET /api/data-quality/issues`
- `GET /api/data-quality/export`
- `POST /api/data-quality/recompute` if useful for UI refresh; can return the same computed summary without persistence.

Implementation requirements:

- Admin/operator can access; viewer should not.
- Query filters: `module`, `severity`, `limit`.
- CSV export follows existing admin export pattern.

Acceptance:

- Summary and issue endpoints return stable shape.
- Export returns `text/csv`.
- Unauthorized role behavior follows existing auth/role taxonomy.

### Task 3 - Dashboard And Report Caveats

Integrate compact `data_quality` caveats into:

- `backend/services/dashboard_metrics.py`
- `backend/services/management_reports.py`

Implementation requirements:

- Additive fields only; do not remove or rename existing response keys.
- Data quality object includes status, counts, caveats, and top issues.
- Keep computation bounded to avoid slow dashboard/report calls.

Acceptance:

- Existing dashboard operational tests pass.
- Existing management report tests pass.
- New tests assert caveat presence for warning/critical seed data.

### Task 4 - Import Preview Quality Impact

Extend import preview surfaces:

- `backend/routers/planning_data.py` for PO Batubara and Merit Order.
- `backend/routers/coa.py` for combined COA preview.

Implementation requirements:

- Add `data_quality` summary to preview payloads.
- Reuse existing preview `issues` arrays; do not alter existing issue contract.
- Do not automatically block commit unless existing validation already fails.

Acceptance:

- PO/Merit preview tests still pass and new tests assert data-quality impact.
- COA combined preview test covers warning/critical quality summary.

### Task 5 - Frontend Data Quality Monitor

Add `frontend/src/pages/DataQualityPage.js`.

Implementation requirements:

- Route `/data-quality` in `frontend/src/App.js` for admin/operator.
- Sidebar link in `frontend/src/components/Layout.js` for admin/operator.
- Page shows severity summary, module/severity filters, issue list, refresh/recompute, export, and Indonesian empty/error states.
- Use existing app components/styles and lucide icons.

Acceptance:

- Text wraps and controls do not overlap on common desktop/tablet/mobile widths.
- Export downloads CSV.
- Viewer role is not allowed to access the route.

### Task 6 - Tests, Verification, And Docs

Add `backend/tests/test_data_quality.py`.

Coverage:

- clean dataset returns healthy/zero critical issues
- warning dataset reports missing/stale/unrealistic issue
- critical COA delta/negative value reports critical issue
- API summary/issues/export work with role gate
- dashboard/report payload includes additive data-quality caveat
- import preview includes data-quality impact

## Threat Model

- Do not expose secrets or raw hidden Mongo `_id` values in issues/export.
- Role gate data-quality APIs to admin/operator.
- Keep scans bounded to avoid production latency spikes.
- Do not block imports silently; display impact clearly and preserve existing commit semantics.
- CSV output must quote cells to avoid malformed export rows.
