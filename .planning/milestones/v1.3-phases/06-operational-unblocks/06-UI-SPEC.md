# Phase 6 — UI Design Contract

> Visual and interaction contract for the AI Chat History UI (OPS-04) and
> Indonesian-localized error UX cross-cut (OPS-02). Generated by
> gsd-ui-researcher. Consumed by gsd-planner and gsd-executor.

## Executive Summary

Phase 6 adds two UI surfaces to the existing EMITS frontend (React 19 + craco +
Tailwind + shadcn/Radix + sonner + lucide-react):

1. **AI Chat History Page** (`/ai-chat`) — a new route with sidebar + main panel
   layout displaying cross-session per-user conversation history from the
   canonical `ai_chat_history` MongoDB collection (ADR-012). The sidebar lists
   conversations recent-first; the main panel shows messages for the selected
   conversation with lazy-load on scroll-to-top.

2. **Indonesian-localized error toasts** — a cross-cutting pattern applied to
   all AI endpoints (OPS-02): LLM-unavailable (503), auth-expired (401), and
   network-failure toast messages in Bahasa Indonesia, using the existing
   `sonner` toast instance already mounted in `App.js`.

This contract extends existing patterns — it does NOT introduce new fonts,
design tokens, component libraries, or third-party registries. Every visual
decision below is derived from scanning the live codebase
(`pltu-tenayan-full-backup/frontend/src/`) and the `design_guidelines.json`
design token file.

## Typography

All sizes use existing font families declared in `index.css`. No new fonts.

**Font-weight constraint:** Maximum 2 weights — 400 (regular) and 700 (bold).
`font-normal` (400) is used for all body text, labels, timestamps, indicators,
and headings except the page h1. `font-bold` (700) is used exclusively for the
Rajdhani page title h1. Weight 500 (`font-medium`) and weight 600
(`font-semibold`) are NOT used in the Phase 6 chat UI. The size + color
contrast provides sufficient hierarchy without intermediate weights.
(`index.css` line 1 confirms Rajdhani loads weights 500/600/700 — 700 is
available and safe.)

Panel is `flex-1 min-w-0`.

**Props:** none (route component)

**State:**

| State | Type | Initial | Description |
|-------|------|---------|-------------|
| `conversations` | `Array<Conversation>` | `[]` | List of user's conversations from GET /api/ai/conversations |
| `selectedConvId` | `string \| null` | `null` | ID of currently-selected conversation |
| `loadingConversations` | `boolean` | `true` | True while fetching conversation list |
| `error` | `string \| null` | `null` | Top-level fetch error |

**Data types:**
```js
// Conversation list item (from GET /api/ai/conversations)
{
  id: string,          // conversation_id
  title: string,       // auto-generated from first user message (≤50 chars)
  last_message_at: string  // ISO 8601 datetime
}
```

**Behavior:**
- On mount: fetch `GET /api/ai/conversations`. On success: set
  `conversations`; set `selectedConvId` to `conversations[0].id` (most
  recent). On empty array: set `selectedConvId = null` (show EmptyState).
- On "Percakapan Baru" click: call `POST /api/ai/conversations`. On success:
  prepend returned conversation to list, set `selectedConvId` to new id.
- Pass `selectedConvId` and `onSelectConversation` callback to sidebar; pass
  `selectedConvId` to panel.

**Accessibility:** `<main role="main">` is already provided by `Layout.js`.
The inner flex container needs no additional role.

### 5. `MessageList`

**File:** `pltu-tenayan-full-backup/frontend/src/components/ai-chat/MessageList.js`

**Purpose:** Scrollable, chronological message list. Oldest messages at top,
newest at bottom. Auto-scrolls to bottom on new messages. Lazy-loads older
messages when user scrolls to top.

**Props:**

| Prop | Type | Required | Description |
|------|------|----------|-------------|
| `messages` | `Array<Message>` | yes | All loaded messages; oldest-first order |
| `loading` | `boolean` | yes | Shows skeleton list on initial load |
| `loadingOlder` | `boolean` | yes | Shows spinner at top while fetching older |
| `hasMore` | `boolean` | yes | Hides "Awal percakapan" sentinel when true |
| `onLoadOlder` | `() => void` | yes | Called when scroll reaches top |
| `sending` | `boolean` | yes | Shows "AI sedang mengetik..." indicator |

**Scroll behavior:**
- Container: `overflow-y-auto` with `ref` for programmatic scroll.
- On initial load: scroll to bottom (`scrollTop = scrollHeight`).
- On new message appended: scroll to bottom with `scrollIntoView({ behavior: 'smooth' })` via `chatEndRef.current`.
- On lazy-load older messages: preserve scroll position. Before inserting older
  messages at top, record `scrollHeight`; after insert, set
  `scrollTop = newScrollHeight - prevScrollHeight` to prevent jump.
- Scroll-to-top detection via `IntersectionObserver` on a sentinel div at the
  very top of the list (calls `onLoadOlder` when sentinel enters viewport;
  guarded by `hasMore && !loadingOlder`).

**Skeleton (initial load):** 3x `MessageBubbleSkeleton` alternating user/AI
alignment — `Skeleton` component with `className="h-16 rounded-xl"`.

**AI typing indicator:** Shown at the bottom of the message list when
`sending === true`, below all messages:
```jsx
<div aria-live="polite" aria-label="AI sedang memproses">
  <span className="text-[11px] text-slate-500 italic animate-pulse">
    AI sedang mengetik...
  </span>
</div>
```

**Structure:**
```jsx
<div ref={containerRef}
     className="flex-1 overflow-y-auto overflow-x-hidden p-4"
     role="log"
     aria-label="Pesan percakapan"
     aria-live="polite">
  {/* Top sentinel for lazy-load */}
  {hasMore && <div ref={topSentinelRef} className="h-1" />}
  {loadingOlder && (
```

### Helper Utilities

**`src/lib/formatRelativeTime.js`** — new file:

```js
import { differenceInSeconds, differenceInMinutes, differenceInHours,
         differenceInDays, format } from "date-fns";
import { id } from "date-fns/locale";

export function formatRelativeTime(isoString) {
  const date = new Date(isoString);
  const now = new Date();
  const secs = differenceInSeconds(now, date);
  if (secs < 60) return "baru saja";
  const mins = differenceInMinutes(now, date);
  if (mins < 60) return `${mins} menit yang lalu`;
  const hrs = differenceInHours(now, date);
  if (hrs < 24) return `${hrs} jam yang lalu`;
  if (hrs < 48) return "kemarin";
  const days = differenceInDays(now, date);
  if (days < 7) return `${days} hari yang lalu`;
  return format(date, "dd MMM yyyy", { locale: id });
}
```

`date-fns` and `date-fns/locale` are already in `package.json` (`^4.1.0`).

## State Management Approach

**Pattern: local component state + prop drilling** — matches the existing app
pattern in `AIIntelligencePage.js` (useState + useEffect + axios; no Redux, no
Zustand, no React Query). No new global state is introduced.

**Data flow:**
```
AIChatPage (owns: conversations, selectedConvId, loadingConversations)
  └── ConversationSidebar (receives: conversations, selectedConvId, onSelect, onNew, loading)
        └── ConversationListItem (receives: conversation, isSelected, onClick)
  └── ConversationPanel (receives: conversationId, conversationTitle)
        internal state: messages, loading, sending, hasMore, oldestMessageId, inputValue
        └── MessageList (receives: messages, loading, sending, hasMore, onLoadOlder)
              └── MessageBubble (receives: message)
        └── MessageInputBar (receives: value, onChange, onSend, disabled)
        └── EmptyState (receives: onNewConversation, creating)
```

**No custom Context needed.** `useAuth()` is consumed directly in `AIChatPage`
and `ConversationPanel` to get `getAuthHeader()`. This follows the exact pattern
in `AIIntelligencePage.js:84`.

**Error state:** Each data-fetching call (GET list, GET messages, POST message)
handles errors locally via `try/catch` + `toast.error(...)` from sonner. No
global error state. Network errors are classified at the catch site:

```js
try {
  const res = await axios.get(..., { headers: getAuthHeader() });
  // ...
} catch (err) {
  if (!err.response) {
    // Network error
    toast.error("Tidak terhubung ke server.", { action: { label: "Coba lagi", onClick: retry } });
  } else if (err.response.status === 401) {
    toast.error("Sesi habis. Silakan login ulang.");
    navigate("/login");
  } else if (err.response.status === 503) {
    toast.error("Layanan AI tidak tersedia", {
      description: err.response.data?.detail ||
                   "Layanan AI sementara tidak tersedia. Silakan coba lagi sebentar.",
      action: { label: "Coba lagi", onClick: retry }
    });
  } else {
    toast.error("Terjadi kesalahan pada server. Silakan coba lagi.");
  }
}
```

## API Integration Shape

### Authentication

All requests include: `Authorization: Bearer <token>` via `getAuthHeader()`
from `AuthContext`. Per ADR-004.

### Endpoint 1: List Conversations

```
GET /api/ai/conversations
Authorization: Bearer <token>

Response 200:
[
  {
    "id": "conv_abc123",
    "title": "Analisis stok batubara terbaru",   // first ~50 chars of first user message
    "last_message_at": "2026-05-11T04:00:00Z"    // ISO 8601
  },
  ...
]
// Sorted: newest last_message_at first
// If no conversations: returns []

Response 401: { "detail": "..." }  → re-login flow
Response 5xx: error toast
```

### Endpoint 2: Get Messages (paginated)

```
GET /api/ai/conversations/<id>/messages?before=<message_id>&limit=20
Authorization: Bearer <token>

// First page: omit ?before (returns newest 20)
// Subsequent pages: ?before=<id of oldest message currently displayed>

Response 200:
[
  {
    "id": "msg_xyz789",
    "role": "user",          // "user" | "assistant"
    "content": "Berapa total stok...",
    "created_at": "2026-05-11T03:59:00Z"
  },
  ...
]
// Sorted: oldest first within the returned page
// If fewer than 20 returned: hasMore = false (reached beginning)
// If exactly 20 returned: hasMore = true (assume more exist)

Response 404: conversation not found → show EmptyState, clear selectedConvId
Response 401: re-login flow
Response 5xx: error toast
```

**Client-side `hasMore` logic:** If `response.data.length < 20`, set
`hasMore = false`. If `response.data.length === 20`, set `hasMore = true`.

### Endpoint 3: Create New Conversation

```
POST /api/ai/conversations
Authorization: Bearer <token>
Content-Type: application/json
Body: {}   // empty — backend creates conversation record and returns id

Response 201:
{
  "id": "conv_newxyz",
  "title": "Percakapan tanpa judul",    // default until first message sent
  "last_message_at": "2026-05-11T04:46:00Z"
}

Response 401: re-login flow
Response 5xx: error toast
```

### Endpoint 4: Send Message

```
POST /api/ai/conversations/<id>/messages
Authorization: Bearer <token>
Content-Type: application/json
Body:
{
  "content": "Berapa total penerimaan batubara bulan ini?"
}

Response 200:
{
  "id": "msg_newmsg",
  "role": "assistant",
  "content": "Berdasarkan data terbaru...",   // LLM response; may contain markdown
  "created_at": "2026-05-11T04:46:05Z"
}
// Backend also persists user message; client uses its optimistic version

Response 503:
{
  "detail": "Layanan AI sementara tidak tersedia. Silakan coba lagi sebentar."
}
→ Remove optimistic user message; show LLM-unavailable toast per D-10

Response 401: re-login flow
Response 5xx: remove optimistic message; show generic error toast
Network failure: remove optimistic message; show network-error toast
```

### Error Mapping Table

| HTTP Status | `err.response` | User-facing action |
|-------------|---------------|-------------------|
| No response (`!err.response`) | undefined | Toast "Tidak terhubung ke server." + "Coba lagi" |
| 401 | `err.response.status === 401` | Toast "Sesi habis. Silakan login ulang." + `navigate("/login")` |
| 503 | `err.response.status === 503` | Toast title "Layanan AI tidak tersedia" + description from `err.response.data.detail` + "Coba lagi" |
| Other 4xx/5xx | otherwise | Toast "Terjadi kesalahan pada server. Silakan coba lagi." |

## Performance Budget

VPS constraint: 4 GB RAM (~1.8 GB available + 4 GB swap), 2 vCPU.
Frontend served as static build via nginx.

| Metric | Budget | Notes |
|--------|--------|-------|
| Initial page load (`/ai-chat`) | <2 seconds | No new npm packages; build size unchanged |
| Conversation list fetch | <500ms | Simple MongoDB aggregate; assume <100 docs |
| Initial message load (20 msgs) | <800ms | MongoDB find with limit=20 + sort |
| Lazy-load older messages | <500ms | Indexed cursor query by msg_id |
| Message render per item | <16ms (1 frame @ 60fps) | ReactMarkdown is pre-installed; no new parsers |
| React-markdown re-render guard | Memoize `MessageBubble` with `React.memo` | Prevents full list re-render on new message |
| Lazy-load chunk size | 20 messages | Locked per D-17 |
| Max messages rendered simultaneously | 200 | Beyond this, consider windowing (deferred to Phase 8); 10 current records mean this is not a concern in v1 |
| Textarea auto-grow calculation | Synchronous; <1ms | DOM height read/write; acceptable |

**Bundle impact:** Phase 6 adds zero new npm packages. All imports (`ReactMarkdown`, `date-fns`, `sonner`, `lucide-react`, `Radix Sheet`) are already in `package.json`. Build size impact: ~5–10 new component files, net +~15 KB minified JS (estimate).

**Memoization contract:**
- `MessageBubble`: `React.memo(MessageBubble)` — re-renders only when `message.id` or `message.content` changes.
- `ConversationListItem`: `React.memo(ConversationListItem)` — re-renders only when `isSelected`, `conversation.title`, or `conversation.last_message_at` changes.
