## Tasks

### Task 1 - Dashboard Quick Actions And Data Quality State

Update `frontend/src/pages/Dashboard.js`.

Implementation requirements:

- Add compact quick action tiles under dashboard header for stock, PO schedule, dispute/umpire, management report, and data quality.
- Use live metrics from existing `operationalStats`.
- Add compact data-quality caveat when dashboard payload reports warning/critical quality.
- Preserve existing filters and primary cards.

Acceptance:

- Primary monitoring workflows are reachable with one click from first viewport.
- Data-quality risk is visible before deeper charts.

### Task 2 - Stable Dashboard And Report Layout Polish

Update `frontend/src/pages/Dashboard.js` and `frontend/src/pages/LaporanPage.js`.

Implementation requirements:

- Add stable min-height/overflow/wrap classes where cards/tables hold dynamic Indonesian text.
- Keep advisor/trend groups readable on desktop/tablet.
- Avoid nested decorative card patterns.

Acceptance:

- Text wraps inside containers.
- Primary dashboard/report grids remain compact and stable.

### Task 3 - Laporan Hook Warning Cleanup

Update `frontend/src/pages/LaporanPage.js`.

Implementation requirements:

- Convert `fetchData` and `fetchSuppliers` to `useCallback` with explicit dependencies.
- Update `useEffect` dependencies to use those callbacks.
- Preserve pagination/filter behavior.

Acceptance:

- Frontend build no longer reports `LaporanPage.js` fetch hook warnings.

### Task 4 - Warning Register And Verification Docs

Update `docs/quality/REACT_HOOK_WARNINGS.md` after build.

Implementation requirements:

- Remove or update the `LaporanPage.js` row based on actual build output.
- Keep remaining legacy warnings documented with rationale.

Acceptance:

- Warning register matches the build warning set.

- Do not broaden scope into risky all-page hook refactors without regression coverage.
- Keep dashboard/report navigation role-compatible with existing routes.
