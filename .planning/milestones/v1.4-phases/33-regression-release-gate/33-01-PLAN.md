# Plan 33-01: One-Command Regression And Release Gate

## Objective

Close v1.4 with a single local release gate that operators can run before
tagging/deploying. The gate must run focused backend regressions, frontend
warning-budget build, smoke verification or a clear skip, and write a compact
artifact summary.

## Tasks

1. Release gate command.
   - Add `ops/scripts/release_gate.py`.
   - Run repo hygiene first.
   - Run focused backend pytest groups sequentially.
   - Run frontend `npm run build:checked`.
   - Run smoke check when backend health is reachable; otherwise record a skip
     reason.

2. Artifact summary.
   - Write JSON and Markdown artifacts under ignored `ops/release-artifacts/`.
   - Include git SHA/tag, dirty status, step statuses, warnings/skips, and next
     action.

3. Test support.
   - Add unit coverage for release-gate helpers.
   - Seed operator/viewer test users in the isolated test backend so auth role
     regressions can run reliably.

4. Documentation and closure.
   - Update production runbook with the release gate command.
   - Run validation.
   - Mark REG4 requirements complete and create Phase 33 summary/verification.

## Acceptance Criteria

- `python3 ops/scripts/release_gate.py` is the one-command release gate.
- Backend focused regressions run in groups that cover auth, dashboard, COA/import,
  reports, data quality, trends, advisor, runtime status, and rekap sorting.
- Frontend `build:checked` runs and enforces the hook warning register.
- Smoke check runs when services are reachable, or the artifact contains a clear
  skip reason.
- JSON/Markdown artifacts include command results, warnings/skips, git metadata,
  and next action.
