# Requirements: EMITS — PLTU Tenayan Fuel Management

**Defined:** 2026-05-10
**Core Value:** Operators and admins at PLTU Tenayan can trust the system as the single source of truth for fuel-receipt data, COA reconciliation, and AI-assisted decision support — every record they enter or upload survives reliably, every report exports cleanly, and login/auth never gets in the way.

## v1 Requirements

This v1 round is **stabilization-first**. Existing PRD-shipped features are kept as Validated (in PROJECT.md). The active v1 requirements below are the work needed to reach a documented, tested, stable system that is ready for upgrade work.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Replace MongoDB with another datastore | IMPLICIT-001 holds; live production data scale + scope does not justify migration |
| Replace FastAPI / React stacks | IMPLICIT-002, IMPLICIT-003 hold; incremental refactor only |
| Switch off Gemini via legacy-ai-sdk | IMPLICIT-005 holds for this round; abstraction is v2 |
| Real-time websockets / live collaboration | Not part of operational workflow; data is batch + form-driven |
| Native mobile app | Web-first remains the policy; deferred to v2 |
| Multi-tenant deployment | Single-plant scope (PLTU Tenayan) — multi-plant is v2 |
| Inline test credentials in committed files | Security: PRD ships test credentials inline (literal values only in `pltu-tenayan-full-backup/memory/test_credentials.md`); replicating in any committed artifact is a leak |
| Horizontal scale / split MongoDB host | Single-host VPS topology fits current load; revisit if RAM/IO bottleneck appears |
| Replacing the Smart Blending mathematical contract | CONS-blending-formula is locked; only operational fixes (OPS-01/02) are in scope |
