    Build the final ENDPOINT_AUDIT.md by reconciling the live OpenAPI surface against API_REFERENCE.md and adding live probe results.

    Test credentials live in pltu-tenayan-full-backup/memory/test_credentials.md (gitignored). Source them at probe time only; NEVER inline them into ENDPOINT_AUDIT.md or any committed artifact. The audit file documents endpoint behavior, not secrets.

    Procedure:

    1. Build the union of paths: cat both .work/*-paths.txt files together, sort -u. This is the master row set for the inventory table.

    2. For each path, extract from openapi.json (using jq) the HTTP methods, the operationId, and any security requirement (presence of `security` on the operation indicates auth-required).

    3. Probe each endpoint live to derive a status:
       - For all GET endpoints with no path parameters and not in the auth-bypass set:
         curl -sS -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $TOKEN" http://103.150.197.225:8013&lt;path&gt;
         where $TOKEN is obtained once at the top of the script via:
         TOKEN=$(curl -sS -X POST http://103.150.197.225:8013/api/auth/login -H 'Content-Type: application/json' -d "@&lt;tempfile-with-creds-from-memory/test_credentials.md&gt;" | jq -r '.access_token // .token // empty')
         If TOKEN is empty, capture that fact in a "Login probe failed" callout at the top of ENDPOINT_AUDIT.md and continue with unauthenticated probes only — note that auth-required rows are then marked "unverified-auth".
       - For GET endpoints with path parameters ({id}, {record_id}, {shipment}, {session_id}): do NOT probe with a fake id (would generate noise / 404 false signals). Mark status `not-probed-path-param` and rely on OpenAPI presence as the existence signal.
       - For POST/PUT/DELETE endpoints: do NOT mutate live data. Mark status `not-probed-mutating`. OpenAPI presence is the existence signal.
       - For the public endpoints /api/, /api/health, /api/auth/login, /api/auth/register: probe without Authorization header.
       - Status mapping from response code:
         * 200 / 201 / 204 → working
         * 401 → working-auth-required (only valid for endpoints in security set; otherwise → broken-auth-leak)
         * 403 → working-role-gated
         * 404 → broken-not-found (only for paths the OpenAPI doc claims exist)
         * 5xx → broken-5xx
         * connection error → broken-unreachable

    4. Determine role tier per endpoint by reading the corresponding section header / "Required role" notes in API_REFERENCE.md. If API_REFERENCE.md does not specify a role and the OpenAPI security block does not specify scopes, mark role tier as `inferred-any-authenticated` (operator or higher) and add a footnote.

    5. Write pltu-tenayan-full-backup/docs/audit/ENDPOINT_AUDIT.md with this exact structure:

       ```

       **API_REFERENCE source:** pltu-tenayan-full-backup/API_REFERENCE.md
       **Probe method:** GET no-path-param endpoints probed live with bearer token from memory/test_credentials.md (gitignored). Mutating endpoints and path-parameterized GETs verified by OpenAPI presence only — no live mutation performed.

       ## Counts

       - Live /api/* paths: &lt;N&gt;
       - Documented /api/* paths in API_REFERENCE.md: &lt;M&gt;
       - Intersection (documented AND live): &lt;X&gt;
       - Live but undocumented: &lt;Y&gt;
       - Documented but missing live: &lt;Z&gt;

       ## Inventory

       | Path | Methods | Auth | Role tier | Live status | In API_REFERENCE? | Notes |
       |------|---------|------|-----------|-------------|-------------------|-------|
       | /api/health | GET | public | n/a | working | yes | — |
       | /api/vessels | GET, POST, DELETE | required | admin/operator (POST), admin (DELETE-all), any-auth (GET) | working | yes | pagination shape verified ({ items, total, page, page_size, total_pages }) |
       | ... | ... | ... | ... | ... | ... | ... |

       ## Drift: Live but undocumented

       List paths in openapi-paths.txt not in api_reference-paths.txt. One bullet per path with method list.

       ## Drift: Documented but not live

       List paths in api_reference-paths.txt not in openapi-paths.txt. One bullet per path with the section in API_REFERENCE.md where it appears, marked "legacy or doc-drift — Phase 3 must reconcile".

       ## Pagination contract spot-check

       For each live list endpoint that returned 200 in the probe (vessels, barges, trucking, biomassa, po-batubara, merit-order, coa-reconciliation, smart-stock, sumber-pemakaian, ai/sessions if applicable), capture the response top-level keys via:
       curl -sS -H "Authorization: Bearer $TOKEN" '&lt;path&gt;?page=1&amp;page_size=1' | jq -r 'keys | sort | join(",")'
       Record one row per endpoint in a small table:
       | Endpoint | Top-level keys | Matches CONS-pagination-shape? |
       The contract is { items, total, page, page_size, total_pages }. "Matches" = all five keys present. If any are missing, record "no — missing: &lt;keys&gt;".

       ## Public endpoint set

       Confirm the live security model matches CONS-auth-header by attempting an unauthenticated GET against /api/health, /api/, /api/auth/login (POST), /api/auth/register (POST). Record actual response code per endpoint.

       ## Methodology
       ```
