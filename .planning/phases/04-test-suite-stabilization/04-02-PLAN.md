<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test process → spawned Phase-4 backend (port 18013) | Auth tokens cross via Authorization header |
| forged JWT → /api/auth/me | Expired token must be rejected with 401, never 200 |
| admin token → list endpoints | Token must not leak via test log capture |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-auth-bypass-01 | Spoofing | Test could accidentally accept 200 for invalid credentials | mitigate | Each negative-path test asserts the exact failure status code (`assert r.status_code == 401`); no `r.ok` shortcuts; explicit message includes response body excerpt for debugging |
| T-token-replay-01 | Spoofing | Expired token incorrectly accepted by /api/auth/me | mitigate | `mint_expired_token` uses `exp = now - 5min` via PyJWT (the same library `server.py` uses); test asserts 401 explicitly. If server.py changes JWT validation to bcrypt-only or another algorithm in future, the helper accepts an `algorithm` parameter for forward-compat |
| T-token-leak-via-log-01 | Information Disclosure | Failed-assertion message could leak the bearer token in pytest output | mitigate | Assertion messages include `r.text[:200]` and `r.status_code`, NOT the request headers; the bearer token is in `admin_headers` (a session fixture) and is never str()'d in failure messages |
| T-pagination-shape-drift-01 | Tampering | An endpoint silently drops `total_pages` field; tests still pass with looser shape | mitigate | `assert_pagination_shape` checks for ALL 5 keys explicitly: "Pagination envelope missing key 'total_pages'" — drift fails loudly |
| T-page-size-injection-01 | Tampering | Negative or absurdly-large page_size value crashes the endpoint | accept | FastAPI's `Query(50, ge=1, le=...)` enforces 422 on invalid values; this plan adds the `test_invalid_page_rejected` assertion to confirm the validator is wired correctly. Beyond that, page_size injection is server-side validation responsibility (ADR-008 cap of 500/50000) |
</threat_model>
