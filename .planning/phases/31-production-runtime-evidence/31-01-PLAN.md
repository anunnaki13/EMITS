# Plan 31-01: Runtime Evidence Artifact, Release Metadata, And Manual Gate

## Objective

Close production runtime evidence debt by making the VPS runtime check produce durable artifacts, keeping smoke status visible through the admin API/UI, exposing backend and static frontend build metadata, and documenting the v1.4 release/manual gate.

## Tasks

1. Runtime evidence artifact.
   - Update `ops/scripts/runtime_status.sh` to create a timestamped runtime report artifact under a configurable evidence directory.
   - Ensure the script prints both runtime report and smoke JSON evidence paths.

2. Release/build metadata.
   - Extend backend runtime status to expose backend build metadata with a safe git fallback.
   - Extend static frontend runtime status to read a served `version.json` when available.
   - Update deploy/build docs or scripts so `version.json` is produced during static deploy.

3. Runtime UI.
   - Update `RuntimeHealthPanel` to show backend build and static frontend build separately.
   - Keep the latest smoke status visible and compact for admin Settings.

4. Runbook and manual gate.
   - Update `docs/operations/PRODUCTION_RUNBOOK.md` with the exact v1.4 release gate.
   - Document artifact paths, fallback steps, evidence retention, and manual gate when real VPS execution is unavailable.

5. Verification and closure.
   - Update backend runtime status tests for metadata shape and secret-free output.
   - Run shell/Python/backend/frontend validation commands.
   - Create Phase 31 summary and verification docs, mark OPS4 complete, and route to Phase 32.

## Acceptance Criteria

- Runtime status command preserves a full report artifact and prints its path.
- Smoke status recording remains available through `/api/admin/runtime/smoke-report`.
- Settings runtime panel shows backend and frontend build/release identifiers.
- Production runbook has an explicit v1.4 runtime evidence gate and manual fallback.
- Validation records local checks and the real VPS manual gate clearly.
